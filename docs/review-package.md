# 合伙人评审包 · Fine Bridge 律师事务所智能体

**评审目标**：在开工前，由律所合伙人确认项目的**业务范围、合规边界、预算、工期**四件大事，并在最后签字定稿。

**预计评审时间**：30 分钟（执行摘要 5 分钟 + 决策项 15 分钟 + 签字 10 分钟）

**评审材料**：
- 本文件（评审引导 + 决策项 + 签字表）
- [`requirements.md`](./requirements.md) — 需求说明书（详读）
- [`architecture.md`](./architecture.md) — 解决方案（速读 §0、§3、§8）
- [`acceptance-and-training.md`](./acceptance-and-training.md) — 验收与培训（速读 §1、§4、§7、§12）

## 一、执行摘要（5 分钟）

### 1.1 项目要做什么

为律所搭建一套**所内浏览器访问**的 AI 辅助办案系统，覆盖案件**全生命周期**（接案 → 卷宗 → 问答 → 文书 → 庭审准备 → 跟踪 → 结案），核心引擎为 **Claude API**。

### 1.2 一句话价值

> **把律师从"查法条、写文书、催期限"中解放出来，把精力还给"判断、谈判、出庭"。**

| 改变 | 现状 | 上线后目标 |
| --- | --- | --- |
| 接案到立案耗时 | 5-7 天 | 减少 30% |
| 文书起草耗时 | 4-8 小时/份 | 减少 50% |
| 期限逾期事故 | 偶发 | 0 |
| 利冲漏检 | 偶发 | 0（系统强制） |
| 助理培训周期 | 4 周 | 2 周 |

### 1.3 8 大模块一览

```
┌──── 业务正面 ────┐    ┌──── 运营底盘 ────┐
│ 1. 案件管理 P0   │    │ 2. 账户管理 P0   │
│ 3. 卷宗上传 P0   │    │ 8. 使用手册 P0   │
│ 4. 智能问答 P0   │    └──────────────────┘
│ 5. 文件输出 P0   │    ┌──── 进阶能力 ────┐
└──────────────────┘    │ 6. 商务报价 P1   │
                        │ 7. 虚拟法庭 P1   │
                        └──────────────────┘
```

### 1.4 关键数字

| 项 | 数字 |
| --- | --- |
| 工期 | **12.5 周**（单全栈工程师，至 MVP 上线） |
| 硬件投入 | **≤ ¥30,000**（一次性） |
| API 月费 | **USD 200-500**（启用 Prompt Caching 后，节省约 75%） |
| 用户规模 | 3-5 人，扩展上限 10 人 |
| 部署位置 | **所内局域网** + Tailscale 异地 |
| 数据合规 | 案件内容**会发送至 Claude API**（境外）；提供"敏感案件不上 AI"开关 |

### 1.5 一张图看清楚最大的合规权衡

```
                ┌─────── 选项 A：全部上 AI ───────┐
                │  ✅ 效率最大化                   │
                │  ❌ 全部案件内容发送境外         │
                │  ❌ 当事人需签数据出境告知书     │
                └──────────────────────────────────┘

   推荐 →   ┌─────── 选项 B：可开关上 AI ─────┐
                │  ✅ 律师按需勾选"敏感不上 AI" │
                │  ✅ 涉密案件系统层强制拦截    │
                │  ⚠️ 律师承担分类判断责任      │
                └───────────────────────────────────┘

                ┌─────── 选项 C：全部不上 AI ──────┐
                │  ✅ 完全合规，零数据出境          │
                │  ❌ 失去 AI 价值，等于不做项目    │
                └───────────────────────────────────┘
```

> **当前方案默认 B**。如合伙人选择 A 或 C，工期与价值会显著变化，请在 §三 决策项 D-01 表态。

> 不必通读 3 份文档。按以下清单逐条勾选即可覆盖关键风险点。

打开 [`requirements.md`](./requirements.md)，确认：

- [ ] **§1.2 业务目标**：5 个目标是否符合律所战略？
- [ ] **§2.2 用户角色**：4 类角色（admin/partner/lawyer/assistant）权限边界合理？
- [ ] **§3 功能需求**：P0 功能（必做）是否有遗漏？P1 功能（可后做）是否有需要提到 P0 的？
- [ ] **§4.4 合规要求**：5 项合规措施是否符合本所执业纪律？
- [ ] **§5.1 业务规则**：7 条法律规则有无错漏（特别是 BR-01 风险代理禁止类型、BR-02 上诉期）？
- [ ] **§8 风险登记**：7 项风险及缓解是否可接受？

### 2.2 验收与培训核查（5 分钟）

打开 [`acceptance-and-training.md`](./acceptance-and-training.md)，确认：

- [ ] **§4 验收用例库**：用例覆盖是否符合"什么算交付完成"的预期？
- [ ] **§6 缺陷分级**：上线门槛 P0=0 / P1≤3 / P2≤10 是否认可？
- [ ] **§7 安全自查清单**：16 项是否要补充/删减？
- [ ] **§12 培训日程**：两周 11 节课程是否能与日常办案错峰？
- [ ] **§14 通关考核**：每位用户必须通过对应角色考核才能正式开账号——是否认可这条硬性纪律？
- [ ] **§18 试运行支持期**：30 天厂商支持承诺是否充分？

### 2.3 红线核查（5 分钟）— 必须全部 OK 才能开工

- [ ] **R1 数据合规**：愿意请客户签署"AI 数据出境告知书"
- [ ] **R2 律师责任**：所有 AI 输出由执业律师审核签发，作为执业行为承担最终责任
- [ ] **R3 涉密拦截**：涉国家秘密、国安、未成年隐私等案件**禁止上 AI**，由律师在系统中标注
- [ ] **R4 备份责任**：每日备份 + 异地副本 + 季度恢复演练，不得跳过
- [ ] **R5 离职即禁用**：员工离职当日由 admin 立即禁用账号、移交案件
- [ ] **R6 不公网暴露**：MVP 期间仅局域网 + Tailscale，不开公网入口
