## 第一部分：验收计划（Acceptance Plan）

### 1. 验收目标

确认交付物满足《需求说明书》的全部 P0 与不少于 80% 的 P1 需求，且系统在真实业务场景下稳定可用、安全合规、易于维护。

### 2. 验收阶段

```
开发完成 → 内部 QA → 试点验收 → UAT 验收 → 正式上线 → 试运行验收
   2 周        1 周        2 周         2 周          1 个月
```

| 阶段 | 责任方 | 关键里程碑 |
| --- | --- | --- |
| **内部 QA** | 开发团队 | 自动化测试通过率 ≥ 95%；冒烟测试全过 |
| **试点验收** | 1 名律师 + 1 名助理 | 完成 3 个真实案件全流程走查 |
| **UAT 验收** | 全所成员 | 完成验收用例库 100%（详见 §4） |
| **正式上线** | 项目组 | 数据迁移 + 全员账号开通 + 培训完成 |
| **试运行验收** | 律所合伙人 | 30 天内 P0/P1 故障 = 0；满意度 ≥ 4/5 |

### 3. 验收准入条件

签署 UAT 启动前必须满足：
- [ ] 所有 P0 功能开发完成并通过内部 QA
- [ ] 部署到生产环境（非本地开发机）
- [ ] 完整的种子数据（至少 5 个示例案件、20 个示例卷宗）
- [ ] 用户手册 v1.0 完成
- [ ] 备份脚本可执行并通过 1 次恢复演练
- [ ] 性能测试报告达 NFR-PERF 目标
- [ ] 安全自查清单（§7）全部通过

### 6. 缺陷分级

| 等级 | 定义 | SLA |
| --- | --- | --- |
| **P0 阻断** | 核心功能不可用、数据丢失、安全漏洞 | 24 小时内修复 |
| **P1 严重** | 主要功能受影响但有变通 | 3 工作日内修复 |
| **P2 一般** | 体验问题，不影响功能 | 下个 Sprint 修复 |
| **P3 改进** | 优化建议 | 排入产品池 |

**上线门槛**：P0 = 0；P1 ≤ 3；P2 ≤ 10。

### 7. 安全自查清单（上线前必过）

- [ ] HTTPS 全站启用，HTTP 自动跳转
- [ ] 密码哈希算法为 bcrypt(cost ≥ 12) 或 argon2
- [ ] JWT 密钥强度 ≥ 256 位，存于环境变量
- [ ] Anthropic API Key 存 macOS Keychain，不在代码或 .env 中
- [ ] 数据库用户仅授予应用所需最小权限
- [ ] 应用层敏感字段加密（身份证号、银行卡号）
- [ ] 磁盘 FileVault 已启用
- [ ] 备份脚本测试通过且备份文件 GPG 加密
- [ ] 端口仅暴露 443 + Tailscale，5432 / 6379 / 9000 仅本机
- [ ] 依赖项无已知高危 CVE（npm audit / pip-audit）
- [ ] CORS 白名单仅含信任域
- [ ] 文件上传白名单（MIME + 后缀双重校验）
- [ ] 每个 API 端点都有鉴权检查（除 `/healthz`）
- [ ] RBAC 越权测试通过（非管理员尝试管理操作 → 拒绝）
- [ ] 速率限制启用（API + Claude 调用）
- [ ] 日志中不记录密码、token、API Key、当事人身份证号

### 14. 通关考核标准

每位用户必须通过对应角色的考核才能获得正式账号权限。

#### 14.1 lawyer 通关清单（30 分钟）
- [ ] 创建一个新案件，录入 2 名当事人
- [ ] 上传 3 份卷宗（含 1 份扫描件，需触发 OCR）
- [ ] 在智能问答中提问并获得引用法条的回答
- [ ] 用模板生成一份起诉状，导出为 .docx
- [ ] 完成一次虚拟法庭至少到"法庭辩论"阶段
- [ ] 在使用手册中找到"上诉期计算"章节

#### 14.2 assistant 通关清单（20 分钟）
- [ ] 接受被分配的案件
- [ ] 上传 5 份卷宗并按类别分类
- [ ] 维护案件时间线，添加 3 条事件
- [ ] 用模板生成一份律师函

#### 14.3 partner 通关清单（20 分钟）
- [ ] 浏览全所案件列表，按律师筛选
- [ ] 审批 1 份报价单
- [ ] 标记 1 份文书"已审核"
- [ ] 配置"敏感案件不上 AI"开关

#### 14.4 admin 通关清单（半天）
- [ ] 从空环境完成一次部署
- [ ] 创建/禁用/重置用户
- [ ] 执行一次手动备份并验证文件
- [ ] 模拟数据库故障并从备份恢复
- [ ] 查看监控仪表盘并解读 Claude 用量

### 15. 培训效果评估

每次培训结束发放问卷（5 分制）：
- 内容清晰度
- 节奏合理度
- 实用性
- 讲师讲解
- 后续意愿（"我能独立操作此模块"评分）

合格线：所有维度均分 ≥ 4.0；后续意愿 ≥ 4.0。否则补训。

### 16. 持续培训机制

- **新人入职**：1 对 1 集中培训 1 天，由 admin 或资深用户带教
- **季度回顾**：每季度 1 次"使用习惯回顾会"，1 小时
- **新功能上线**：每次大版本更新发布"What's New"邮件 + 30 分钟在线讲解
- **使用反馈**：手册"是否有用"反馈每月汇总，识别培训盲点
