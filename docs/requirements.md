## 1. 项目背景与目标

### 1.1 业务背景
律师事务所日常工作涉及大量重复性、规则性的文档处理与流程管理：接案咨询、卷宗整理、法律检索、文书起草、庭审准备、案件跟踪、结案归档。传统人工处理存在以下痛点：

| # | 痛点 | 影响 |
| --- | --- | --- |
| 1 | 法律检索效率低 | 律师 30-40% 时间花在查法条、找类案 |
| 2 | 文书起草重复劳动多 | 同类型文书反复手写，质量参差 |
| 3 | 期限管理依赖人工 | 上诉期、举证期逾期 = 执业事故 |
| 4 | 卷宗散落多端 | 微信、邮件、纸质、云盘——查找耗时 |
| 5 | 经验难以沉淀 | 老律师离开/休假，案件难以接续 |
| 6 | 报价与计费不规范 | 客户体验不一致，可能违反风险代理禁令 |
| 7 | 新人培训成本高 | 缺少标准化流程与示例库 |

### 1.2 项目目标

| 目标类型 | 具体目标 | 衡量指标 |
| --- | --- | --- |
| **效率** | 单案件处理时间下降 | 接案到立案 ↓ 30%；文书起草 ↓ 50% |
| **质量** | 减少程序性失误 | 期限逾期 = 0；利冲未查 = 0 |
| **合规** | 全流程可追溯 | 100% 关键操作有审计记录 |
| **沉淀** | 经验数字化 | 结案后案例自动入库可检索 |
| **培训** | 新人快速上手 | 助理培训周期 4 周 → 2 周 |
| **客户体验** | 报价与进度透明 | 每案至少 1 次进度通报 |

### 1.3 项目范围

**业务建模（核心）**：系统按律所**三大业务线**组织：
- **① 常年法律顾问**：合同审查、法律意见书、定期工作汇报、法律咨询解答
- **② 诉讼仲裁案件代理**：案件分析与资料处理、司法文书输出（含反诉、管辖异议、证据目录与三性、再审、执行、仲裁、规范性文件等全套）、模拟法庭打磨
- **③ 非诉法律项目**（**核心差异化模块，业主主战场**）：股权并购等项目的尽调清单、尽调报告、法律意见书、交易文本、配套文本

**In Scope（MVP 必须包含）—— 10 大模块**：

通用底座（跨业务线）：账户管理、客户与卷宗、智能问答、文件输出、商务模块、使用手册

业务线模块：法律顾问服务模块、诉讼仲裁案件管理、非诉法律项目模块、虚拟法庭（外脑）

- 内嵌的 `legal-firm-agent` Skill（已在 `skills/legal-firm-agent/SKILL.md`）
- 配套模板含 `templates/legal-non-litigation-project.md`（非诉项目尽调清单、尽调报告、SPA 骨架、配套文本清单）
- 浏览器访问（无独立桌面/移动端 App）
- 所内局域网部署 + Tailscale 异地访问

**Out of Scope（明确不做）**：
- 公网部署、多租户 SaaS
- 移动端原生 App
- 实时音视频虚拟法庭（一期为文字流式）
- 本地大模型部署（统一走 Claude API）
- 财务/票据系统集成（一期手工录入）

## 2. 干系人与用户角色

### 2.1 干系人

| 干系人 | 职责 | 关注点 |
| --- | --- | --- |
| 项目发起人 | 决策、预算 | ROI、合规风险、上线节奏 |
| 律所合伙人 | 业务最终用户 + 验收 | 易用性、法律准确性、客户口碑 |
| 主办律师 | 高频使用者 | 工作效率、AI 输出质量 |
| 律师助理 | 高频使用者 | 流程指引清晰、模板可复用 |
| IT 负责人 | 部署、运维 | 稳定性、备份、扩容 |
| 当事人（间接） | 受益方 | 进度透明、隐私保护 |
| 开发团队 | 实施 | 需求清晰、技术可行 |

### 2.2 用户角色与权限

| 角色 | 主要场景 | 权限 |
| --- | --- | --- |
| `admin` | 系统初始化、用户管理、备份恢复 | 全部 |
| `partner`（合伙人） | 全所案件审视、报价审批、最终签发 | 所有案件可见可编辑 |
| `lawyer`（律师） | 主办/协办案件、AI 问答、文书起草 | 仅自己关联的案件 |
| `assistant`（助理） | 卷宗整理、台账维护、模板填充 | 仅被分配案件，受限编辑 |
| `client`（当事人） | 查看本案进度、上传材料（二期） | 极受限 |
